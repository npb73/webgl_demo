## О чём это

Шестнадцать записей в трёх частях: как устроен код WebGL, что даёт страница-текстура (и как на этом собран сам сайт) и что из этого брать в свой проект. Короткий текст, аналогии из привычного фронтенда и живые демо в бумажных окнах. Окна таскаются за заголовок, меняют размер, разворачиваются на весь экран (кнопка слева от крестика или двойной клик по заголовку) и пропускают клики сквозь себя.

Сайт — презентация: на экране один слайд, длинные записи разбиты на несколько экранов («2 из 3» на полях). Листать — стрелками ← → в правом нижнем углу или клавишами <kbd>←</kbd> <kbd>→</kbd> и <kbd>PageUp</kbd> / <kbd>PageDown</kbd> (их же отправляют пульты для презентаций). Номер слайда — в адресе (`#lens-2`), так что ссылка и перезагрузка ведут на тот же слайд. Если слайд не влезает в окно, он уменьшается через CSS `zoom`.

## Включите флаг в Chrome

Шейдеры, искажающие страницу, используют экспериментальный API [HTML-in-Canvas](https://github.com/WICG/html-in-canvas): браузер отрисовывает HTML внутри `<canvas>` в текстуру.

1. Откройте `chrome://flags/#canvas-draw-element` и включите флаг.
2. Перезапустите браузер.

Без флага сайт работает как обычная страница: читаются все слайды, работает график, а окна-эффекты показывают подсказку про флаг.

## Как это устроено

**Вся страница — внутри одного canvas.** С флагом страница становится `drawable`-потомком `<canvas>`, прибитого к экрану. Браузер верстает её как обычно, а на экран её выводит WebGL: в текстуру попадает открытый слайд — и только когда браузер его перерисовал. Прокрутки нет намеренно: снимок длинной страницы стоил ~12 мс на каждый кадр прокрутки (слайд «Сколько это стоит»), а листание слайда — один снимок экрана. Клики, ховеры и выделение текста работают, потому что браузеру сообщают, где элемент нарисован.

**Окна — слои той же сцены.** Рамку окна браузер рисует в текстуру один раз, а положение и содержимое задаёт сцена. Перетаскивание ничего не перерисовывает в DOM — меняется одна матрица. Шейдер окна получает подложку: всё, что нарисовано под окном.

**Переходы — две текстуры и сетка.** При листании сцена копирует текстуру страницы, а слайд сменяется мгновенно. Следующие 2–3 с вместо страницы рисуется кадр перехода: старая и новая страница на сетке из треугольников (загиб листа, грани куба) или на облаке точек. Окна и линзы видят переход под собой, как обычную страницу.

**Карточки — свои слои сцены.** Каждая карточка товара — drawable-элемент прямо в canvas, а место в вёрстке слайда держит пустой блок. Сцена снимает карточку в текстуру, ставит туда, где этот блок, наклоняет в 3D за указателем и накладывает эффект из [`product-card.frag`](shaders/product-card.frag). Перед кадром карточки впекаются в текстуру страницы, поэтому переходы и линзы видят их как её часть.

**Milkdrop без своих цветов.** Пресеты из коллекции [butterchurn-presets](https://github.com/jberg/butterchurn-presets) считает движок [butterchurn](https://github.com/jberg/butterchurn), тот же, что в [Webamp](https://github.com/captbaritone/webamp). Он работает в крошечном скрытом canvas, а сцена забирает из него только сетку «откуда брать прошлый кадр». Каждый кадр окна — прошлый кадр, сдвинутый по этой сетке, плюс 7% свежей страницы. Вместо музыки — случайный сигнал в формате звука.

**Шейдеры лежат в .wasm.** GLSL-исходники из [`shaders/`](shaders/) упаковываются в WebAssembly-модули скриптом [`scripts/build-shader-wasm.mjs`](scripts/build-shader-wasm.mjs). В браузере JS читает строки из памяти модуля и компилирует их как обычный GLSL.

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
```

| Команда | Что делает |
| --- | --- |
| `npm run dev` | dev-сервер; перед стартом пересобирает шейдеры |
| `npm run build` | статическая сборка в `out/` |
| `npm run shaders` | только упаковать `shaders/*.vert` + `*.frag` в `public/shaders/*.wasm` |
| `npm run lint` | ESLint |

## Структура

```
shaders/                 GLSL: эффекты окон, сцена, переходы, график, Milkdrop
scripts/                 упаковка шейдеров в .wasm
app/
  page.tsx               слайды
  content/               тексты и данные слайдов
  components/
    Stage/               сцена: страница в canvas, окна, эффекты
    PaperWindow/         бумажное окно (DOM-режим и слой сцены)
    Milkdrop/            пресеты, поле движения, случайный «звук»
    Plot/                график на миллион точек
    Slide/               слайд размером с экран, уменьшение под окно
    SlideNav/            стрелки листания и номер слайда
    TransitionPicker/    кнопки переходов между слайдами
    ProductCards/        карточки товаров: слои сцены с 3D-наклоном
    ScreenshotDemo/      скриншот кадра: вспышка, миниатюра, скачивание
    ResourceMonitor/     живые счётчики сцены: кадры, снимки, видеопамять
  lib/webgl/             загрузка .wasm, компиляция шейдеров
  lib/page-transition.ts выбранный переход: связь стрелок и сцены
docs/screenshots/        картинки для этого README
```

## Деплой

Каждый пуш в `main` собирает сайт и публикует его на GitHub Pages: [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml). Сайт живёт в подпапке репозитория, поэтому сборка получает путь через `PAGES_BASE_PATH`. Локально переменная не нужна.
